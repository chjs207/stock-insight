# 스탁인사이트 — 로컬 웹서버

KOSPI·KOSDAQ 기업 재무와 자산운용사 지분공시, 키움 주가 차트 또는 네이버 증권 차트를 조회하는 개인용 도구입니다. **실제 서비스는 사용자 PC에서 실행하며, GitHub 저장소는 코드 백업용으로만 사용합니다.** GitHub Pages와 Actions로 수집·호스팅하지 않습니다.

## 필수: 프로젝트의 .env에 DART 인증키 입력

**기업 검색·재무·공시 조회에는 프로젝트 폴더의 `.env`에 본인의 OpenDART 인증키를 입력해야 합니다.** GitHub의 Security / Actions Secrets는 이 버전에서 사용하지 않습니다. 키는 Node 서버에서만 읽으며 브라우저로 전달하지 않습니다.

Node.js **24 이상**과 npm이 필요합니다. 처음 설치할 때 프로젝트 폴더에서 실행합니다.

```sh
npm ci
cp .env.example .env
```

복사한 `.env`에 실제 발급받은 **DART 키**를 입력합니다. **키움증권 API가 없다면 키움 키를 입력하지 않고 네이버 증권 차트를 이용합니다.** 복사된 파일의 `KIWOOM_APP_KEY`, `KIWOOM_APP_SECRET` 항목은 삭제하거나 값을 비워 두면 됩니다. 아래는 키움 키 없이 사용하는 기본 설정 예시이며, DART 예시 값은 본인의 실제 인증키로 바꿔야 합니다.

```dotenv
# 금융감독원 OpenDART에서 발급한 인증키
DART_API_KEY=your_opendart_api_key

# 이 PC에서만 접속하는 기본 설정
HOST=127.0.0.1
PORT=4180
DATABASE_PATH=.local/stock-insight.sqlite
```

키움 키 없이 서버를 실행한 뒤 기업 상세의 **주가 차트 → 차트 방식 → 네이버 증권 → 네이버 차트 열기**를 선택합니다. 해당 종목의 공식 차트를 새 탭에서 볼 수 있습니다. 네이버 차트 연결에는 API 키가 필요하지 않습니다.

**키움 API 차트를 사용하는 경우에만** 아래 두 항목을 `.env`에 추가하고 실제 발급받은 값을 입력합니다. 키움증권 API가 없으면 추가하지 않습니다.

```dotenv
KIWOOM_APP_KEY=your_kiwoom_app_key
KIWOOM_APP_SECRET=your_kiwoom_app_secret
```

- [OpenDART 인증키 신청](https://opendart.fss.or.kr/)
- [키움 REST API 이용 안내](https://openapi.kiwoom.com/intro/serviceInfo)
- 키움 API 차트를 이용할 때는 **이 서버 PC의 공인 IP**를 키움 허용 IP로 등록해야 합니다. 내부망 주소 `192.168.x.x`가 아닙니다. 유동 IP가 바뀌면 키움 홈페이지에서 등록 정보를 갱신합니다. 네이버 차트 연결에는 키움 허용 IP 등록이 필요하지 않습니다.
- `.env` 변경은 서버를 종료하고 다시 실행해야 반영됩니다.
- DART 키를 빠뜨리거나 예시 값 그대로 두면 시작 시 안내합니다. 키움 키가 없거나 예시 값이면 키움 최신 자료 조회 시 설정 안내를 표시하며, 네이버 연결은 사용할 수 있습니다.

## 실행

```sh
npm run build
npm start
```

PC 브라우저에서 **http://127.0.0.1:4180/** 을 엽니다. 종료는 실행한 터미널에서 `Ctrl+C`입니다. 다른 프로그램이 4180 포트를 사용하면 `.env`의 `PORT`를 변경합니다.

소스를 수정한 뒤에는 서버를 종료하고 `npm run build` 후 다시 시작합니다. `npm run dev`는 화면을 다시 빌드한 뒤 같은 로컬 서버를 시작하는 편의 명령입니다.

## 같은 내부망의 모바일에서 사용

PC와 휴대폰을 같은 Wi-Fi 또는 내부망에 연결하고 다음 명령으로 실행합니다.

```sh
npm run build
npm run start:lan
```

터미널에 표시되는 `http://192.168.x.x:4180/` 같은 **내부망 접속 주소**를 안드로이드·아이폰 브라우저에 입력합니다. 이 명령은 `.env`의 `HOST` 대신 `0.0.0.0`을 사용하지만, 서버가 확인한 사설망의 같은 서브넷과 로컬 접속만 허용합니다. PC IP가 바뀌면 서버를 다시 시작하고 새 주소를 사용합니다.

PC가 켜져 있고 서버가 실행 중일 때 사용할 수 있습니다. 같은 서버에 접속한 기기는 하나의 관심종목과 DB를 공유합니다. 내부망 모드는 접속한 내부망 기기를 신뢰하는 개인용 구성입니다. 인터넷 포트 포워딩이나 공개 서버 배포용 로그인 기능은 포함하지 않습니다.

## 기능

상단 메뉴는 **재무검색 → 거인의 어깨 → 기업 리서치 → 52주 신고가 → 관심종목** 순서입니다. 재무검색에서 기업을 찾아 재무·주가 차트를 확인하고 관심종목을 등록합니다. 기업 상세 화면에서도 재무검색 탭이 선택되며, 별도의 관심종목 탭에서 등록 목록 확인·차트 바로 열기·등록 해제를 관리할 수 있습니다. 상세 화면의 **관심종목 목록** 링크로 목록에 돌아갈 수 있습니다.

관심종목에서 기업을 열면 상세 메뉴에 **기업 재무 · 주가 차트 · 기업 리서치**가 표시됩니다. 기업 리서치를 선택하면 별도 검색 없이 해당 기업의 종목코드로 보고서를 바로 조회하며, 페이지 이동과 최신 조회에서도 이 기업만 유지합니다. 상단의 기업 리서치 메뉴에서는 여러 기업과 키워드를 자유롭게 검색할 수 있습니다.

- 기업명·종목코드 검색과 관심종목 등록·해제
- 연간 5개년 매출액·영업이익·순이익·지배주주 순이익, 금액·증감률 전환 차트
- 분기 기본 2년, 확장 버튼으로 1년씩 추가, 전년 동분기·직전 분기 비교
- PER·POR: 최근 연간 또는 연속 4분기 합산(TTM) 기준
- 거인의 어깨: 최근 3년 운용사별 지분공시, 브이아이피자산운용 기본 제공, 운용사 추가·삭제
- 기업 리서치: 네이버 증권 보고서 목록, 기업명·키워드 검색, 페이지 이동, 상세 보고서 연결
- 키움 캔들·거래량 차트: 일봉·주봉·월봉, 기간 선택·이동·확대
- 주가 차트에서 **키움 API / 네이버 증권** 선택, 마지막 선택은 브라우저별로 저장
- 종가 이동평균: 최대 5개, 기간 1–600봉, 색상·표시 설정
- 직전 저점·고점 수평선과 마지막 종가의 등락률

운용사는 **운용사 추가 → 공시 제출인명 입력 → 공시 조회 → 내역 확인 → 이 운용사 등록** 순서로 추가합니다. 조회 결과에는 최근 3년의 기업 수·공시 수, 접수일, 보고서명과 실제 제출인명을 표시합니다. 처음에는 최근 10건을 보여주며 전체 내역도 펼칠 수 있습니다. 조회만으로는 운용사가 등록되지 않습니다.

조회 내역이 0건이면 등록할 수 없습니다. 공시 목록이 덜 수집된 경우에는 ‘내역 없음’과 구분하여 안내하므로 **공시 목록 갱신** 후 다시 조회합니다. 이미 등록된 운용사는 중복 추가 대신 해당 운용사 화면으로 이동할 수 있습니다.

기존 운용사는 **자산운용사 선택 → 운용사 삭제 → 운용사명 확인 → 삭제** 순서로 등록 목록에서 제거합니다. 취소하면 유지됩니다. 기본 제공되는 브이아이피자산운용도 삭제할 수 있고, 삭제 상태는 서버를 다시 시작해도 유지됩니다. 수집된 공시와 보유 현황은 보존하므로 나중에 공시 조회 후 다시 등록할 수 있습니다. 공시가 0건인 기존 등록도 삭제할 수 있습니다.

**거인의 어깨** 옆의 **기업 리서치** 탭에서 네이버 증권의 보고서 목록만 스탁인사이트 화면으로 표시합니다. 기업명·보고서 제목·증권사·작성일·목표주가·투자의견을 볼 수 있고, 20건 단위 이전·다음 페이지 이동을 지원합니다. 제목을 누르면 네이버 상세 보고서가 새 탭에서 열립니다. [네이버 원본 목록](https://stock.naver.com/research/company)으로 이동하는 버튼도 제공합니다.

검색 방식은 **기업명**과 **키워드**로 구분합니다. 기업명 검색에서는 기업명 또는 6자리 종목코드로 기존 기업 검색을 이용합니다. 검색된 기업이 하나면 바로 조회하고, 여러 개면 기업을 선택합니다. 선택한 종목코드를 네이버 목록 전체에 적용하므로 해당 기업 보고서만 조회되며 페이지 이동·최신 조회에도 유지됩니다. 기업 검색은 기존 로컬 기업 DB를 우선 사용하고 필요한 경우 DART를 조회합니다. 키워드 검색은 네이버의 제목·본문 등 키워드 검색을 사용하므로 그 단어가 언급된 다른 기업의 보고서도 포함될 수 있습니다.

리서치 목록은 기업 종목코드·키워드·페이지를 구분하여 로컬 DB에 10분간 저장하며, **최신 목록 조회**는 최소 30초 간격으로 갱신합니다. 네이버 연결이나 응답 형식 확인에 실패하면 저장된 목록과 안내를 표시합니다. 보고서 본문과 PDF는 수집하지 않습니다. 네이버 리서치 조회에는 DART·키움 키를 전송하지 않으며, 네이버의 공개 목록 구조가 변경되면 연동 수정이 필요할 수 있습니다.

## 연간·분기 실적 그래프

연간·분기 모두 **금액**을 기본으로 표시합니다. 연간은 조회된 5개년을 모두, 분기는 기존과 같은 개별 3개월 실적을 표시하며 분기 표에서 연도를 확장하면 그래프에도 추가됩니다.

- **매출액**과 **이익** 그래프를 분리하고 각각의 금액 축을 사용합니다. 원화는 **억 원** 단위이며 적자는 0선 아래로 표시합니다.
- 이익 그래프는 영업이익·순이익·지배주주 순이익을 함께 보거나 하나씩 선택할 수 있습니다.
- 그래프의 연도·분기를 누르면 아래 선택 실적에서 **금액과 전년 대비/전년 동분기 대비 증감률**을 함께 표시합니다.
- **금액 / 증감률**로 전환할 수 있고, 분기 증감률은 **전년 동분기 / 직전 분기** 비교를 지원합니다. 직전 분기 모드에서도 선택 실적에는 전년 동분기 대비 수치를 함께 표시합니다.
- 자료 없음은 빈 구간으로 표시합니다. 비교 기준이 다르거나 비교 금액이 0이면 증감률은 비교 불가로 표시합니다. 여러 통화가 있으면 표시 통화를 선택해 같은 통화의 금액만 그립니다.

## 로컬 데이터와 API 사용

### 52주 신고가 메시지 조회

상단 **52주 신고가** 탭에서 텔레그램 메시지를 붙여넣고 **기업 목록 조회**를 누릅니다. 기업명·종목코드를 기존 DART 기업 목록과 연결하며, KOSPI·KOSDAQ 상장 여부를 확인합니다. 메시지에서 붙인 신고가 분류를 사용하는 기능이며 실제 52주 최고가 도달 여부를 새로 계산하는 기능은 아닙니다.

`보안) 기업명, 기업명 (실적) 기업명-메모`처럼 분류와 설명이 섞인 형식을 지원합니다. 괄호 안 분류·하이픈 뒤 메모는 별도로 표시하고, 대소문자 차이를 무시하며 중복 기업은 한 행으로 합칩니다. 기업명과 종목코드가 충돌하거나, 동명 상장기업이 여러 개이거나, 일치하는 기업이 없으면 **확인 필요**로 남깁니다. 부분 이름을 임의로 다른 기업에 연결하지 않습니다. 새 상장기업 등이 누락되면 **기업 목록 갱신 후 조회**를 사용하고, 실제 종목코드를 확인해 다시 입력합니다.

각 기업에서 **재무 · 차트 · 리서치**를 새 탭으로 열거나 **관심종목 +**로 직접 등록할 수 있습니다. 조회만으로 관심종목에 등록하지 않습니다. 기업 목록과 확인한 기업 정보는 기존 로컬 DB를 우선 사용하므로 재조회 시 같은 기업에 대한 DART 호출을 줄입니다. 재무·차트 자료는 해당 메뉴를 열 때 조회합니다.

메시지는 로컬 서버의 JSON 본문으로 전달하며 텔레그램 API나 로그인은 사용하지 않습니다. 원문과 분류·메모를 DART·키움·네이버에 전송하지 않습니다. 입력한 원문은 현재 브라우저 탭의 임시 저장소에 보관해 화면 이동 후 다시 붙여넣을 필요를 줄이며, **입력 비우기**로 제거할 수 있습니다. 메시지 원문과 조회 목록의 날짜별 이력은 DB에 저장하지 않습니다. 한 번에 원문 20,000자, 입력 항목 300개, 후보 기업 100개까지 처리합니다. 기업 목록 강제 갱신은 최소 30초 간격입니다.

### 기존 캐시 정책

SQLite DB는 최초 시작 시 자동으로 생성·업데이트됩니다. 기본 파일은 `.local/stock-insight.sqlite`이며, 관심종목·기업 정보·재무제표·지분공시·시가총액·차트를 저장합니다. DB 파일은 실행 폴더 안에 있고 GitHub에 업로드하지 않습니다. DB 경로를 변경하면 다른 DB를 사용하게 됩니다.

검색 시 로컬 DB에 있는 자료를 우선 사용하고 필요한 경우에만 API를 호출합니다. 재무자료는 7일 후 정정 보고서를 재확인하고, 자료 없음은 하루 후 재확인합니다. 시가총액과 차트는 15분 동안 저장본을 사용합니다. 예약 수집이나 GitHub Actions 실행은 필요하지 않습니다.

### 차트 방식 선택

기업 상세의 **주가 차트 → 차트 방식**에서 선택합니다. 기본값은 기존과 같은 **키움 API**입니다. 선택은 현재 브라우저에 저장되어 다른 기업을 열거나 새로고침해도 유지되며, 같은 서버를 쓰는 다른 기기의 선택에는 영향을 주지 않습니다. 브라우저 저장소를 사용할 수 없어도 현재 화면에서는 전환할 수 있습니다.

**키움증권 API가 없는 경우에는 `.env`에 키움 키를 넣지 않고 `네이버 증권`을 선택해 차트를 이용합니다.** 처음에는 키움 방식이 선택되어 있을 수 있으므로 네이버 증권으로 변경해 주세요. 이후에는 같은 브라우저에서 마지막 선택을 유지합니다.

**키움 API**는 기존 캔들·거래량·이동평균 설정·직전 저점/고점 비교를 이 화면에 표시합니다. `ka10081`로 최근 최대 5년의 KRX 수정주가를 연속 조회합니다. 주봉·월봉은 저장된 일봉을 합산합니다. `최신 자료 조회`는 30초의 최소 간격을 적용하며, 조회 실패 시 기존 차트와 실패 안내를 표시합니다. 키움 키·접근 토큰은 서버 메모리에서만 사용합니다. 주문·계좌 조회·자동매매 기능은 없습니다.

**네이버 증권**은 **네이버 차트 열기** 버튼으로 해당 종목의 [공식 차트 페이지](https://m.stock.naver.com/fchart/domestic/stock/005930)를 새 탭에 엽니다. 네이버를 선택한 상태에서는 키움 차트 API를 호출하지 않습니다. 네이버에 API 키를 전달하거나 차트 데이터를 로컬 DB에 수집하지 않으며, 네이버가 제공하는 차트와 설정을 사용합니다. 키움 방식으로 다시 전환하면 기존 로컬 차트와 저장된 이동평균 설정을 사용할 수 있습니다.

직전 고점·저점은 양옆 봉보다 높은 고가·낮은 저가를 가진 가장 최근 확정 구간입니다. 같은 가격이 이어진 구간은 하나로 보며 마지막 봉 날짜를 사용합니다. 가장 최근 봉만으로는 새 고점·저점을 확정하지 않습니다.

4분기는 같은 연결·별도 기준과 통화의 연간 실적에서 3분기 누적 실적을 빼서 계산합니다. PER는 연결 지배주주 순이익(별도는 순이익), POR는 영업이익을 사용하며 양수 이익에 대해서만 계산합니다. 시가총액은 네이버 증권의 보통주·식별 가능한 우선주 합산 저장본을 사용합니다. 로컬 캔들 차트 데이터 출처는 키움이며, 네이버 선택 시 네이버 원문 차트에 연결합니다.

## 기존 데이터 가져오기

기존 서버의 SQLite 또는 이전 수집기의 `cache.json`을 새 DB에 가져올 수 있습니다. 원본 파일은 읽기 전용으로 열며 수정하지 않습니다. 같은 보고서가 있으면 더 최근에 수집된 기록을 우선하고 기존 관심종목을 보존합니다.

```sh
npm run db:import -- --from "/기존/프로젝트/.wrangler/state/v3/d1/miniflare-D1DatabaseObject/기존DB.sqlite"
npm run db:import -- --from "/기존/프로젝트/.data/cache.json"
```

가져오기와 DB 백업은 서버를 종료한 상태에서 수행하는 것을 권장합니다. DB를 백업할 때는 서버 종료 후 `.local` 폴더를 복사합니다. 이동평균 설정은 브라우저 저장소에 보관하므로 기기별로 따로 관리합니다.

## GitHub 코드 백업과 비공개 자료

- 저장소는 Public이며 소스 코드를 공개합니다. GitHub는 코드 공유·백업용으로 사용하고, 실제 인증키와 개인 DB·수집 자료는 로컬에서만 보관합니다.
- `.env.example`의 예시와 소스만 커밋합니다. 실제 `.env`, 다운로드한 키 파일, `.local`, `.data`, `.wrangler`, DB·백업 파일, 실행 로그, `dist`는 Git에서 제외합니다.
- GitHub Pages 게시와 Actions 수집·배포 워크플로는 제거했습니다. 이전 `data` 브랜치는 로컬 DB로 이전하고 `.local/legacy-github-data.bundle`에 복구 가능한 이력 백업을 보관했습니다. 이 백업도 GitHub에 업로드하지 않습니다.
- 웹서버는 빌드된 화면과 정해진 API만 제공합니다. `.env`, DB, 백업, 소스 파일을 웹 주소로 내려주지 않습니다.
- 기존 GitHub Secrets를 유지하더라도 이 로컬 서버는 그 값을 사용하지 않습니다.
